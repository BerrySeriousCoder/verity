# 0010: Compact evidence and shared bidirectional comparison work

Accepted and implemented for new reviews (batching version 3).

- Inventory and independent coverage audit still each read every block, without seeing each other's output. Compact responses use local integer source/category references and grouped exclusions; deterministic expansion rejects unknown references and omitted blocks. Both observation sets remain in the ledger.
- Exact duplicate observations with identical source IDs, title, category and references can share canonicalization work. Distinct qualifications and source documents remain separate. Related observations and checks are sorted together to improve context reuse.
- Initial comparison retrieval uses distinguishing title terms with OR search plus inverse-frequency-ranked counterpart checks restricted to the same confirmed relationship. Initial fan-out is eight search blocks and four counterpart checks instead of twenty and twelve. These are retrieval candidates, never proof of absence. Insufficient evidence still triggers follow-up or an unverified result.
- Unique reciprocal checks with exactly matching normalized title, category, relationship and references may share a comparison unit. Uncertain or individually answered checks are excluded. Both complete original requirements are provided; the reviewer and independent verifier must validate both directions. The original directional ledger entries and source members remain separate. Packet checkpoint identities include every paired check ID to prevent resume collisions.
- Model evidence preserves exact source text, citation IDs and page/sheet location. PDF rendering coordinates remain server-side. Spreadsheet cell data is omitted only when it exactly duplicates the parser's serialized row text; formulas and merged-cell context remain available. Distinct IDs/content never merge. Evidence reference keys and ordering are stable to improve implicit cache opportunities; hits are not guaranteed.
- Verification input omits the duplicate provisional finding. It retains the decision, original requirements, cited evidence, applicability and calculations.
- Persist cached-input tokens, thought tokens, prompt characters, queue time and request duration when supplied. Historical missing cache measurements mean unknown. `pnpm review:usage [run-id ...]` provides stage and run accounting; it does not infer invoice cost or judge accuracy.
- Existing reviews retain their original batching version and completed checkpoints. Model-only evidence projection applies globally without altering source storage. No artificial model output token cap or cheaper-model substitution was added.

Validation: deterministic unit checks and database integration scenarios cover source preservation, invalid IDs/coverage, relationship boundaries, bidirectional ledger expansion, invalid citations, old checkpoint recovery and idempotent usage totals. Real-document quality, cost and latency improvements still require a new comparable completed run; no percentage improvement is claimed.
